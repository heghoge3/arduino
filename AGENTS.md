# Общие инструкции для работы с репозиторием

Сначала прочитать README.md, docs/product.md, docs/STATUS.md, docs/workboard.md
и docs/collaboration.md, затем материалы назначенной области.
Это правила для всех чатов; CLAUDE.md лишь ссылается сюда.

Перед подключением/разводкой/корпусом V2 обязательно читать
[единую электрическую базу — передачу конструктору](docs/hardware-v2/electrical-baseline.md).
Она сверена с s3/0.1.32: различает код/макет/непроверенный экземпляр, содержит актуальные
контакты, ползунок, BOM и проверки E01–E16. Не вести параллельные таблицы распиновки.
USB ESP32 и SD только при открытом корпусе, USB зарядки снаружи (подтверждено 12.11).
Владелец 12.11 разрешил **GPIO14 только для ключа подсветки**; `PIN_LCD_BACKLIGHT=14`
используется и защищён от других назначений. Это единственное исключение для нижних
площадок. С 0.1.32 драйвер AO3401: LOW=ON, HIGH=OFF, 15 с/кнопки/RTC HIGH во сне/reset/OFF;
ключ AO3401 должен иметь внешний pull-up G→S (SYS_3V3) и переключать только LED, не весь LCD.
Внутренняя LED-цепь, ключ и реальное гашение ещё не испытаны. Старые A+B/DS1302 — история.

Для программного направления обязательно читать docs/software.md и
[docs/software-roadmap.md](docs/software-roadmap.md): анализ, последовательность задач,
критерии проверок и открытые решения. Этот список не разрешает автоматически начинать
реализацию; каждый этап отдельно согласуется с владельцем.
Перед задачами интерфейса Android читать [бриф редизайна «ПОЛИМЕР»](docs/app-redesign-polymer.md).
13.11 получены ответы 1–50: ПОЛИМЕР, тёплая оранжевая основа, приборная пиксельность,
тёмная + светлая темы. Последние исключения: метки пока скрыть, хлопушку убрать,
экспорт для монтажа пока убрать; старые данные и остальные функции сохранять.
Q50 разрешает несколько вариантов главной. [Макеты/обоснование](docs/design/polymer-home/README.md)
— отклонены владельцем 14.11.2026, только история. Подходящий дизайн не подготовлен;
работа этого исполнителя остановлена. Не реализовывать отклонённые макеты и не повторять
опрос 1–50. Новая работа — по отдельному поручению владельца. Canva только вспомогательно.
Непроверенные GPS-точки — в «Для разработчика», качество/разрывы не маскировать.
Варианты макетов не являются разрешением на реализацию. Название — в product.md; package/ключи не менять.
Перед задачами BLE OTA читать [действующий контракт V2](docs/ble-ota-v2.md),
[хранение OTA-ключа](docs/ota-signing.md) и этапы OTA1–OTA7 основного списка.
Владелец разрешил полный первый сценарий: код 0.1.32/0.10.9 реализует A/B, подписанный
образ в APK, приём/ACK/retry, отложенную самопроверку и проверку результата после reset.
Первый USB-bootstrap 0.1.29 обязателен **из нового комплекта 0.1.32/wiring2**.
Старые 0.1.29/0.1.30/0.1.31 для AO3401 не использовать; OTA между wiring1/2 запрещён.
OTA-state wiring2 — `ota-v2-r2`; прежний `ota-v2` не удаляется/не исполняется. Рабочая разметка — ota/partitions.csv,
два слота по 1,5 МиБ; адреса разделов данных сохранены. APK-ключ не менялся;
отдельный постоянный OTA-ключ создан, приватно вне git; не создавать замену и не публиковать.
**Ползунок основной**, GPIO3 OFF-input, GPIO7 HOLD для сохранения перед OFF,
не для жеста A+B. Внешний 10 кОм к системным 3,3 В; OFF второй независимой группой на GND.
GPIO3 JTAG-strapping, не boot-mode; eFuse не менять. Legacy A+B только явный исторический профиль.
Программные проверки не доказывают работу EN/reset, flash/SD при обрыве и реальный rollback.
Две копии flash перед USB приватны; USB-подготовка и аппаратная приёмка пока не выполнены.
См. [проверки](docs/software-evidence/2026-11-12/ble-ota-implementation.md).
Эмулятор приложения обновляется на месте под V2; старую реализацию не вести
отдельным пользовательским режимом. Перед задачами эмулятора читать
[docs/emulator-v2.md](docs/emulator-v2.md); симуляция не доказывает готовность железа.
Перед изменениями GPS читать [активную политику 2](docs/gps-policy-v2.md) и
[диагностику](docs/gps-diagnostics.md). В 0.1.25/0.10.6 география только контекст,
непроверенные точки хранятся отдельно, разрывы имеют явный признак в POINT.
Политика 1 оставлена только для старых trace; реальные записи не публиковать.
Полевой приёмки и гарантии обнаружения любой подмены нет; установленная ESP32 неизвестна.
Перед задачами начала/завершения похода и меню также читать
[спецификацию цикла похода](docs/hike-lifecycle.md). Владелец разрешил начать работу
над приложением и прошивкой. Реализованы экран/свежесть и отдельные START/END/RESUME
на прежней аппаратной базе и в Android; текущие проверки — в STATUS.md.
**Уточнение владельца 10.11.2026: единственная цель дальнейшей разработки — V2.**
Не вести отдельную разработку, поддержку или выпуск для V1. Существующий код OLED/
DS1302 — наследие, а не целевой комплект. Цикл похода сохранить и адаптировать сразу
к LCD GM12864-59N (ST7567/ST7567S), DS3231, двум кнопкам, пассивному зуммеру и
выбранному EN/HOLD-питанию V2 по актуальным аппаратным документам. Неподтверждённые
GPIO/адреса/электрические связи не выдумывать. Перед работой читать
[перенос V2 и ограничения запуска](docs/firmware-v2.md): 0.1.22 использует DS3231/ST7567,
В 0.1.23 HOLD назначен на GPIO7 (через D2 к EN) и включён по умолчанию;
подсветка с 0.1.32 управляется GPIO14 через внешний LED-ключ, который ещё надо проверить.
Назначение и драйвер не равны аппаратной проверке. Автономная готовность не подтверждена.
Не назначать внешним подключениям V2 труднодоступные GPIO45, 42, 41, 40, 39, 38,
18, 17, 16, 15 — прямое указание владельца. GPIO14 позже отдельно разрешён только
для подсветки через ключ; не переносить на другие роли. Остальные запрещённые не используются.
Подтверждены: любая кнопка будит экран, гашение через 15 секунд бездействия;
ночью поход продолжается с автоматическим энергосбережением на привале.
Q1 согласован: после сбоя спросить «Продолжить / Завершить».
Q2 для исторического Gesture-профиля: при выключении спросить «Завершить текущий поход? Да/Нет»;
«Нет» выключает с незавершённым походом и вопросом о продолжении при новом включении.
Q2 относится к профилю A+B. В основном профиле ползунка OFF не вызывает
FINISH и не спрашивает подтверждение: сохраняет тот же ID в RECOVERY; следующий ON
спрашивает «Продолжить / Завершить». Ошибка сохранения оставляет HOLD, запись остановлена.
Общая раскладка будущего меню ещё не утверждена; ползунок/HOLD реализован программно, аппаратная работа не подтверждена.
При адаптации V2 проверить сохранение HOLD во внутреннем сне и при пробуждении.

## Приложение, ключ и данные

- Один текущий пакет com.vabugeode.app. Переименование бренда не меняет пакет/подпись автоматически.
- APK собирает и передаёт агент; не перекладывать сборку и настройку Secrets на владельца.
- Старый ключ потерян, его повторно не просить. С APK 0.10.2 используется разрешённый
  владельцем новый постоянный ключ, закреплённый в android/signing-certificate.sha256.
- Не создавать ещё один ключ. Не публиковать ключ, пароль или конфигурацию в git/логах.
- См. docs/android-signing.md; локальные пути прошлой среды не гарантируют наличия файлов.
- Владелец отказался от переноса данных старой установки ради смены подписи;
  специальный импорт для этого перехода не разрабатывать и не считать блокером.
  Импорт SD не реализован; возможные будущие функции SD этим решением не отменены.
  13.11 владелец подтвердил установленный APK 0.10.6 на Infinix Note 30, текст стандартный.
  Установка 0.10.9, версия Android и версия ESP32 не подтверждены; текущий сертификат
  установленного APK и сохранность прежних данных технически не проверялись.
- 11.11.2026 владелец прикрепил рабочую вторую копию резервного архива. Ключ открыт,
  сертификат совпал с контрольным значением. Приватные файлы сохранены вне git в
  /workspace/private-signing; наличие в будущих средах проверять заново. Прямой доступ
  к Library не подтверждён; первая присланная копия ZIP была пустой. См. android-signing.md.
