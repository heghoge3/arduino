# Прошивка vabuGEOde

ESP32-S3-Zero + PlatformIO (Arduino). Логика — [docs/gadget-logic.md](../docs/gadget-logic.md),
протокол — [docs/protocol.md](../docs/protocol.md), ТЗ — [CLAUDE.md](../CLAUDE.md).

> **Ничего из этого ещё не проверено на железе.** Код собирается под ESP32-S3, ядро (протокол, NMEA,
> подмена, шаги, логика состояний, закат) проходит тесты на компьютере. Всё остальное проверяем 30-го.

## Подключение (сверить с шелкографией платы до пайки)

Полная инструкция со схемой, доработками модулей и пошаговым запуском — [docs/assembly.html](../docs/assembly.html)
(открыть в браузере).

| Модуль | Вывод модуля | ESP32-S3-Zero |
|---|---|---|
| Общая шина I²C (BME280, MPU6050, QMC5883L, INA219, OLED) | SDA / SCL | GPIO8 / GPIO9 |
| GPS ATGM336H | TX модуля → / ← RX модуля | GPIO44 (RX) / GPIO43 (TX) |
| GPS питание | затвор AO3401 (+10 кОм к истоку) | GPIO6 (LOW = вкл) |
| SD | CS / MOSI / SCK / MISO | GPIO10 / 11 / 12 / 13 |
| Кнопка A / B (на GND) | | GPIO1 / GPIO2 |
| MPU6050 | INT | GPIO4 |
| Пищалка | + | GPIO5 |
| DS1302 | CLK / DAT / RST | GPIO14 / GPIO15 / GPIO7 |
| Все модули | VCC / GND | 3,3 В / GND |

**Питание:** выход TPS63020 сначала проверить мультиметром — **3,3 В**. Не держать одновременно
включённую батарею и USB (питание идёт мимо стабилизатора платы) — прошивать при выключенной кнопке питания.

## Как прошить

1. Поставить **VS Code** и расширение **PlatformIO IDE**.
2. Открыть папку `firmware/`. PlatformIO сам скачает всё нужное (первый раз ~5–10 мин).
3. Выбрать окружение внизу:
   - `s3` — рабочая прошивка;
   - `s3_fake` — **если пришла только плата**: датчики и GPS эмулируются, можно проверить Bluetooth с телефоном.
4. Подключить плату по USB (батарея выключена) → **Upload**. Если не прошивается — зажать BOOT, нажать RESET, отпустить BOOT.
5. **Monitor** (115200): при старте печатается чип — должно быть `ESP32-S3`.

## Консоль (Monitor)

| Команда | Что делает |
|---|---|
| `help` | список команд |
| `st` | время, режим, датчики, заряд, GPS, подмена |
| `i2c` | сканер шины: ждём 0x0D, 0x3C, 0x40, 0x68, 0x76/0x77 |
| `info` | чип, PSRAM, SD |
| `gps on` / `gps off` / `gps echo` | GPS вручную; `echo` — сырой NMEA (какие системы: GPGSV/BDGSV/GLGSV) |
| `pcas <тело>` | команда модулю GPS, например `pcas PCAS04,3` (сверить с даташитом) |
| `win` | открыть окно BLE с сопряжением (как долгое нажатие B) |

После любой команды гаджет 10 минут не уходит в глубокий сон — иначе USB-монитор отвалится.

## Журнал (отладка)

Гаджет пишет всё, что может понадобиться для разбора: причину каждого включения (сбой прошивки,
сторожевой таймер, просадка питания), смены режимов, GPS (время до фикса, потеря фикса, нет NMEA),
подмену с причинами, пропажу датчиков с шины, ошибки SD, подключения и отказы Bluetooth, команды телефона.
Снимок состояния — раз в минуту в отладке (на стоянке раз в 5 мин), иначе раз в 10 мин.

- На SD: `/logs/ГГГГММДД.log` (текст), `/logs/all.bin` (для приложения). Дневные журналы старше 30 дней удаляются.
- Строки копятся в RTC-памяти и пишутся на SD пачкой; ошибки — сразу. Последние строки перед сбоем
  переживают перезагрузку и попадают на SD после неё.
- Приложение забирает новые строки при каждом подключении: «Трекер → Журнал», там же «Поделиться» файлом
  вместе с журналом телефона.
- В мониторе порта строки видны сразу: `[W GPS] фикс потерян…`. Команды `log` (сбросить на SD), `debug on|off`.

Формат строки: `2026-10-31 14:03:22 +125 I PWR стоянка -> в пути` — время UTC (`?` — не проверено),
секунд с включения, уровень (E/W/I/D), модуль.

## Первый запуск — порядок проверки

1. Только плата, окружение `s3_fake`: чип S3, `info`, телефон видит «vabuGEOde» (долгое B или `win`).
2. По одному модулю, окружение `s3`: `i2c` после каждого подключения; DS1302 — время в `st`; GPS — `gps on` + `gps echo` на улице.
3. Ток в сне и в пути — по INA219 (`st`), сверить с бюджетом в gadget-logic.md, раздел 6.

## Тесты на компьютере

```
pio test -e native
```

Протокол сверяется с `docs/protocol_vectors.json` — теми же байтами, что проверяет приложение.
