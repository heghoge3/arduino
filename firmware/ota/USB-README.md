# V2: первый USB-переход на BLE OTA

Комплект для испытаний, не аппаратно принятый выпуск. Только ESP32-S3 V2,
фактические 4MB flash, ползунок ON/OFF (GPIO3), HOLD GPIO7. EN конкретного модуля,
ON при reset/bootloader, сохранность SD и реальный rollback ещё не проверены.
V1 и произвольные ESP32-платы не поддерживаются.

Полный контракт и матрица обязательных испытаний:
https://github.com/heghoge3/arduino/blob/claude/happy-wozniak-l7x710/docs/ble-ota-v2.md

## Перед записью

1. Сначала проверить независимый ON→EN при reset на макете, USB-развязку, правильные
   уровни GPIO3/HOLD7. Оставить ползунок ON, обеспечить проверенное питание, использовать
   тестовую SD. Копию её файлов сохранить отдельно.
2. Не обновлять во время похода/выгрузки. Если поход незавершён, сначала закончить или
   сохранить его и согласовать тест на отдельной SD. Первая миграция не испытана на приборе.
3. Распаковать весь ZIP. В архиве нет приватного ключа; не добавлять его туда.
   Проверить SHA256SUMS. Файлы bootstrap/ образуют один комплект, не смешивать сборки.
4. Установить зависимости Python (требуется Python 3.10+):

   python3 -m pip install -r requirements.txt

   Windows может использовать `py -3` вместо `python3`.

## Выполнение

Из корня распакованного комплекта:

    python3 tools/prepare_ota_usb.py --port COM5 --backup /PRIVATE/v2-before-ota.bin --confirm-v2 --apply

Заменить COM5 своим портом; Linux, например /dev/ttyACM0. Путь копии — НОВЫЙ файл
в приватной папке вне комплекта/репозитория. Копия flash содержит настройки и BLE-bonds:
не публиковать её. Если среда не умеет права 0600 (Windows), обеспечить доступ только владельцу.
Не использовать erase_flash/форматирование SD и не прошивать app.bin из update/ на старую таблицу.

Скрипт проверяет суммы, чип, размер flash, незашифрованную/без Secure Boot исходную
конфигурацию, делает два одинаковых чтения flash без запуска приложения между ними.
Неожиданные таблица/флаги защиты/дополнительные разделы → отказ до записи.
Поддерживается прежний huge_app проекта и layout1, не любая разметка. eFuse не меняются.
Записываются только bootloader (0x0), partitions (0x8000), boot_app0 (0xE000),
база 0.1.29 (0x10000). NVS0x9000/20K, SPIFFS0x310000, coredump0x3F0000 сохраняются,
внешняя SD не форматируется. Само сохранение адресов не гарантирует сохранность носителя.

0.1.29 — тот же новый OTA-код с отдельной базовой версией, не старая историческая прошивка.
Скрипт ждёт USB и отправляет `ota provision`: явное подтверждение модели/проводки.
Без подтверждённого ответа он сообщает ошибку commissioning, даже если flash уже записан.
При смене номера USB-порта открыть новый порт после загрузки и выполнить
`ota provision` вручную через serial 115200 после самопроверки (не ранее 3 с).
Не повторять всю миграцию ради потерянного ответа. При необходимости ROM download:
BOOT удержать, RESET нажать/отпустить, BOOT отпустить — проверить на своей плате.

Это ОДНОКРАТНЫЙ переход: сразу после USB есть одна рабочая база, старый бинарник
не сохранён как второй rollback-слот. Повторный USB-bootstrap 0.1.29 после уже принятого
нового OTA не является штатным откатом: NVS high-release остаётся и запрещает старые
повторные образы. Для ремонта нужен отдельный аудит фактической версии/копии, не erase-all.

## Затем Android

Установить APK 0.10.9 постоянной новой подписи проекта. Старый APK 0.10.1 нельзя
обновить поверх из-за другого ключа; владелец ранее согласовал удаление старой установки
без специального переноса. Установка не считается выполненной заранее.
Подключиться/сопрячь V2, завершить поход и синхронизацию, проверить батарею (≥50% и 3,8 В).
Открыть Настройки → Прошивка прибора → Проверить → Обновить и подтвердить.
Оставить приложение открытым. APK содержит подписанную 0.1.32, интернет при передаче не нужен.

После FINISH прибор перезапускается, приложение переподключается и проверяет версию,
полный SHA-256 и подтверждение самопроверки. Если питание не удержалось — ручной запуск,
подключение и «Проверить». 100% передачи не является успехом. При обрыве до FINISH
рабочая база остаётся выбранной, следующая передача начинается с нуля по явному действию.
Отключение во время первого запуска может вызвать rollback: приложение покажет фактическую версию.

update/ содержит публичные app-only образ/manifest/public.der, те же, что в APK;
это не merged flash/загрузчик. Приватного OTA-ключа в комплекте нет.
Настоящие испытания включают оба слота, hang/watchdog/откат, отключение питания во всех
окнах, OFF посреди записи на тестовую SD и сравнение NVS/bonds/файлов до/после.

## AO3401: ревизия подключения и резервный слот

Для выбранного владельцем AO3401 GPIO14 **LOW=ON/HIGH=OFF**. Это **wiring revision=2**,
отдельная от прежнего предложения HIGH=ON (revision=1, версии до 0.1.31).
Основной BLE wire=2, OTA wire=1 и layout=1 не менялись: номер проводки — другое поле.
Приложение сравнивает его, приёмник отвергает чужую ревизию до стирания слота.
Обновление wiring1 → wiring2 по BLE не предлагается; новый APK сам не меняет проводку.

Для первого макета использовать **новый комплект 0.1.32**: и USB-база 0.1.29, и
подписанный образ 0.1.32 содержат AO3401-драйвер, wiring2. Не смешивать их с прежними
комплектами 0.1.30/0.1.31. После монтажа AO3401 образ HIGH=ON будет включать свет при
программном OFF/сне; старый образ вообще без драйвера может оставить экран без света.
Старые файлы сохранены для истории, не для установки/отката на эту проводку.

OTA wiring2 использует NVS namespace `ota-v2-r2`: commissioning, transaction,
health и high-release отдельны от `ota-v2` прежней ревизии. Старые OTA-записи не
исполняются и не удаляются; настройки/походы/SD и их пространства не изменены.
Нужно новое явное `ota provision` после проверки wiring2. Номер версии один не
подтверждает правильный bootstrap: сверять комплект, SHA-256 и wiring revision.
Свободное место NVS, сохранность настроек/сопряжения и SD проверяются на макете.

Это путь **первой подготовки**, не автоматическая миграция ранее принятого прибора.
Если wiring1/OTA уже фактически установлены — сначала аудит слотов, private flash-backup,
состояния похода и high-release; не повторять bootstrap/erase-all ради смены полярности.
После первого USB есть один рабочий слот; второй заполняется проверенным OTA.
Откат и свет в обоих слотах, ON/EN при reset и сон проверяются аппаратно.
[Подключение и макетный состав](../../docs/hardware-v2/electrical-baseline.md#lcd-backlight).
