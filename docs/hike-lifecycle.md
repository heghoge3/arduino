# Цикл похода: устройство, две кнопки и приложение

Актуализировано 10.11.2026 по задаче владельца: завершение через приложение и гаджет.
В исходниках **ESP32 0.1.21 / Android 0.10.4 (27)** реализованы отдельные START,
FINISH и RESUME, сохранение состояния и подтверждение действий. Этот этап ошибочно
выполнен на прежней аппаратной базе OLED/DS1302. Владелец уточнил: **целевая прошивка
только V2**, отдельная разработка V1 не нужна. Логику цикла сохранить; интерфейс и
аппаратную часть перенести на LCD/DS3231/EN-HOLD V2. Перенос драйверов 0.1.22 и условный путь питания описаны
в [firmware-v2.md](firmware-v2.md); автономная готовность ещё не подтверждена.
Установка на устройства владельца и аппаратные испытания не подтверждены.
Основной список задач — [software-roadmap.md](software-roadmap.md); проверки и выпуск —
[STATUS.md](STATUS.md), пакеты — [protocol.md](protocol.md). Прежняя спецификация
и исходное поведение сохранены в истории git.

## Что работает сейчас

| Состояние устройства | Запись | Доступные действия |
|---|---|---|
| IDLE: включено, поход не начат | Нет | Начать |
| ACTIVE: поход идёт | По действующим правилам GPS и паузы; CAMP остаётся этим же походом | Завершить; пауза маршрута не завершает поход |
| RECOVERY: незавершённый поход после холодного запуска | Остановлена до решения | Продолжить тот же ID / Завершить |
| ENDED: завершён | Новые точки, шаги и метки в него не добавляются | Просмотр сохранённых данных / отдельно Начать новый |
| ERROR: состояние не прочитано или не подтверждено сохранение в NVS | Остановлена | Диагностика; нельзя создавать новый поверх неизвестного состояния |

BLE, качество GPS, состояние похода и полнота копии телефона независимы.
Потеря связи не завершает поход; по возрасту записи окончание не угадывается.
Любая кнопка будит экран; через 15 секунд бездействия он гаснет, запись продолжается.
Ночёвка не требует завершения: автоматический привал и внутренний сон сохранены.
Первый запуск больше не включает запись автоматически; прежнее правило 6 часов убрано.
После сбоя/разрядки/перезапуска ACTIVE переходит в RECOVERY с вопросом по Q1.
После обычного внутреннего сна остаётся ACTIVE без вопроса. ENDED не возобновляется.
При обновлении старый сохранённый ID переводится в RECOVERY, отсутствие ID — в IDLE;
данные автоматически не стираются.

## Как завершить

**Приложение:** подключить прибор, дождаться свежего состояния и окончания
синхронизации. На главной или вкладке «Походы» нажать «Завершить поход», затем
«Подтвердить». Отмена ничего не отправляет. Успех — только после ответа устройства.
Начало следующего похода — отдельный диалог.

**Прежняя реализация OLED (описание кода, не инструкция для V2):** разбудить экран любой кнопкой и отпустить её. Удержать B
1,5 секунды для страницы «Поход» (также доступна листанием B). Здесь A выбирает
действие, короткое B открывает подтверждение. Для «Завершить» отпустить B и удержать
её заново 1,5 секунды. A отменяет. Удержание, открывшее меню, само ничего не завершает.
Гашение экрана сбрасывает подтверждение. После успеха — «Поход завершён», при отказе —
«Не сохранено!» без ложного перехода в ENDED.

В IDLE/RECOVERY/ENDED страница похода открывается при пробуждении экрана.
«Данные» возвращает к показаниям, «Подключить телефон» открывает сопряжение.
На страницах данных A сохраняет метку/хлопушку только в ACTIVE.
Без обнаруженного OLED удержание B по-прежнему открывает сопряжение; цикл доступен
из приложения, слепого END нет. Большое меню V2 пока не утверждено.

## Сохранение и восстановление

Авторитетный текущий результат — 40-байтовая запись NVS `life`: формат/magic, ревизия,
ID, фаза, время решения END, идентификатор и параметры последней операции, контрольная
сумма. После записи проверяются длина и точное чтение обратно. Проверка API NVS
не заменяет испытаний при просадке питания.

- START проверяет SD, подготавливает файлы, сохраняет переход и включает запись.
  ID больше предыдущего; корректировка часов его не переименовывает.
- FINISH дописывает доступную финальную точку и сбрасывает накопленный хвост CAMP.
  Ошибка SD/оставшийся буфер блокирует подтверждение. Из буфера убираются только
  успешно записанные элементы. Затем сохраняется END в NVS и запись останавливается.
- Копия END пишется в `/tracks/<ID>.end`. Если она не записалась, END остаётся в NVS;
  новый START блокируется до успешного сохранения копии прежнего окончания.
- RESUME сохраняет прежний ID, добавляет точку разрыва без координат и сбрасывает
  привязку дистанции. Неизвестный путь во время отключения не дорисовывается.
- Ожидаемые ID/ревизия и ID операции защищают от устаревшего экрана, повторов и
  одновременных команд. Точный повтор последней операции возвращает сохранённый
  результат. Кнопки и BLE используют один обработчик.
- Повреждённый существующий NVS не принимается за пустую память. Ошибка сохранения
  переводит программу в ERROR до восстановления при следующем запуске;
  неизвестное состояние автоматически не удаляется.

Телефон сохраняет намерение в Room до отправки. Потеря ответа означает неизвестный
результат; после подключения/перезапуска запрашивается состояние без автоматического
повтора команды. Пока результат неизвестен, новые действия заблокированы, доступно
«Проверить результат». Диалог относится к конкретным ID/ревизии.
Миграция Room 4 → 5 сохраняет прежние данные.

END хранится отдельно от точек: даже пустой завершённый поход виден в истории.
После END запрашивается финальный хвост трека/меток; полнота копии и окончание различаются.
Если прибор уже начал следующий поход, телефон запрашивает `.end` прежнего известного
ID. Это **не импорт всей SD**: обнаружения неизвестных телефону походов нет.
Старые записи без END остаются без подтверждения окончания. Защита достижений от удаления
сохранена; последний ID прибора нельзя удалить до начала следующего похода.
Новая прошивка отклоняет совмещённую NEW_HIKE; RECORD работает только внутри ACTIVE.
Новое приложение требует прошивку 0.1.21 для цикла. Старое приложение не умеет этот
контракт: для установки нужен согласованный комплект APK и прошивки.

## Проверки и ограничения

Автотесты покрывают переходы, повторы, устаревшие запросы, отказ записи/чтения
подтверждения, восстановление, потерю ответа, миграцию и подтверждение интерфейса.
Результаты — в STATUS. На реальном V1 ещё проверить:

| Сценарий | Критерий |
|---|---|
| END с телефона и кнопками, на паузе/CAMP | После подтверждения нет новых точек; перезапуск сохраняет ENDED |
| Обрыв BLE до/после END, закрытие приложения | Нет ложного успеха/повтора; после подключения фактическое состояние |
| Одновременные действия двух сторон | Один переход, устаревшая команда отклонена |
| SD заполнена/извлечена, ошибка записи | Нет ложного успеха, несохранённый буфер не очищен |
| Питание исчезло до/после END | RECOVERY либо сохранённый ENDED; нет автоматического нового похода |
| Ночь и многократный внутренний сон | Тот же ACTIVE ID, без лишнего вопроса |
| Пробуждение, удержание, дребезг, гашение экрана | Первое нажатие будит; END требует отдельного подтверждения |
| END без телефона, START и подключение | Прежний известный ID получает окончание из .end |

При внезапной потере питания ещё может теряться буфер CAMP (до 15 точек / 900 секунд
по действующим настройкам). Штатный END сбрасывает его, но общий **Q5: допустимый
объём потери** остаётся открытым. Проверка API не гарантирует сохранность внутреннего
кэша SD при просадке. Восстановление повреждённых файлов/NVS не реализовано;
аварийный обход ошибки SD с потерей данных не добавлен. При недоверенных часах время
END неизвестно (0); это время решения, не угаданное время разрядки. Исходная календарная
дата ID до синхронизации часов может быть неточной, сам ID больше не меняется.

## Полное выключение V2: согласовано, подготовлено условно; аппаратно не проверено

**Q2:** при штатном выключении активного похода спросить
«Завершить текущий поход? Да/Нет». «Да» сначала сохраняет END, затем отключает
основную нагрузку. «Нет» сохраняет незавершённый поход и отключает нагрузку;
после включения спрашивает о продолжении по Q1. Ночёвка остаётся без выключения.

Нужны назначенный и проверенный GPIO HOLD/EN, адаптация нового LCD/RTC, проверка
USB-развязки и сохранения HOLD во внутреннем сне/при пробуждении на макете V2.
Сон/гашение экрана не объявляются полным отключением. В 0.1.22 пункт «Выключить» подготовлен, но скрыт при неназначенном HOLD
по умолчанию; реализация и проверки описаны в firmware-v2.md. Аварийное выключение при зависании/ошибке SD, совместный жест включения
и окончательное меню — отдельные задачи. Другие направления автоматически не запускаются.
