# Электрическая база V2

Обновлено: 2026-11-10. Это историческая карта исходных связей с уточнениями V2, не готовая монтажная схема. Последние ответы владельца меняют батарею, экран и выключатель.

## Изменения владельца

- Прямоугольный LiPo вместо 18650; паспорт и зарядный узел уточнить по новому комплекту.
- Только две кнопки без фиксации. Комбинация нажатий требует отдельной задачи программирования; схему питания без старого выключателя требуется согласовать на уровне аппаратуры.
- Один наружный USB зарядки, SD внутри. Доступ к восстановлению ESP предусмотреть внутри корпуса.
- Новый дисплей: прежний интерфейс OLED не считать гарантированным.
- Модули припаиваются, свободные доступные GPIO выводятся на подписанные площадки; отдельная плата расширения не проектируется.
- Программные режимы и реализация BLE-обновления вне этой задачи.

## Поправка по заказу от 2026-11-09

[Сверка 26 скриншотов](purchased-inventory-2026-11-09.md): куплен модуль с маркировкой DS3231 вместо DS1302. Старые CLK/DAT/CE не переносить в новую схему RTC. DS3231 использует I2C с адресом 0x68. Если сохраняется MPU6050 с историческим адресом 0x68, предусмотреть проверку перевода MPU6050 на 0x69 через AD0; GY-521 и наличие AD0 уже подтверждены фотографиями, электрическое подключение проверить на экземпляре. Изменение интерфейса согласовать с исполнителем прошивки, код здесь не менять.

Компас теперь показан как GY-271 с заголовком QMC5883L, но реальный тип по карточке не установлен. Старый QMC5883P/0x2C не считать подтверждённым для нового комплекта. На схеме продавца GPS написано питание 5V, тогда как историческое ТЗ предполагает коммутируемые 3,3 В; до разводки выяснить вход питания и стабилизатор конкретной платы, не назначать 5V логическим UART-выводам.

Источники: [DS3231](https://www.analog.com/media/en/technical-documentation/data-sheets/DS3231.pdf), [MPU-6050 register map](https://invensense.tdk.com/wp-content/uploads/2015/02/MPU-6000-Register-Map1.pdf).

## GPIO (исторические назначения)

Сверены `pins.h` веток `ccr-faf69fbe-vwugry` и `fix/gps-phone-false-positive`: совпадают.

| Назначение | GPIO ESP32-S3 |
|---|---|
| I2C SDA / SCL | 8 / 9 |
| GPS RX ESP ← TX GPS | 44 |
| GPS TX ESP → RX GPS | 43 |
| GPS EN, LOW включает ключ по ТЗ | 6 |
| SD CS / MOSI / SCK / MISO | 10 / 11 / 12 / 13 |
| Кнопки A / B, замыкание на GND | 1 / 2 |
| MPU INT | 4 |
| Управление пищалкой | 5 |
| DS1302 CLK / DAT / CE | 14 / 15 / 7 |
| RGB | 21 |

I2C-адреса по ТЗ: BME280 0x76, MPU6050 0x68, QMC5883P 0x2C, INA219 0x40, опциональный OLED обычно 0x3C.
Комментарий `pins.h` ещё называет QMC5883L; ТЗ сообщает фактический QMC5883P. Один комментарий не определяет установленный датчик.

## Историческая цепь питания V1 — не переносить без переработки

- CELL+ / CELL− подключены к B+ / B− зарядного модуля.
- OUT+ → выключатель → INA219 VIN+ → шунт → INA219 VIN− → VBAT_LOAD → вход преобразователя.
- OUT− → LOAD_GND; SYS_3V3 — выход преобразователя.
- Питание микросхемы INA219: отдельные VCC / GND, не VIN+ / VIN−.
- GPS_3V3 коммутируется отдельным ключом от SYS_3V3.
- B− и OUT− не объединять в обход защитного узла.

## До финальной схемы проверить

1. Реальные схемы зарядки/защиты, преобразователя и S3-Zero.
2. Развязку USB ESP и внешних 3,3 В, обратные токи и возможную работу во время зарядки.
3. Фактические пики нагрузки и бюджет расширения; диапазон измерения INA.
4. GPS-ключ, подтяжку и поведение UART при выключении GPS.
5. Тип пищалки и нужный драйвер.
6. Подтяжки I2C на всех модулях и выбранную скорость.
7. Резервную батарейку RTC и отсутствие нежелательного заряда.
8. Доступ к тыльным площадкам S3-Zero для расширения.

Обязательный разъём 2×8 из исходного ТЗ отменён. Выводить реально доступные свободные GPIO на подписанные площадки без объёма под расширение. Монтаж нижних контактов S3 требует реального решения.

В `config.h` ветки `fix/gps-phone-false-positive` прочитана версия 0.1.19.
Установленная на приборе версия неизвестна. Версии исходников и сборок: [STATUS.md](../STATUS.md).

## Электронное выключение

Требуется защита от отключения одиночным нажатием. По новой задаче владельца
10.11.2026 выполнены [подбор решения](button-power-selection.md) и
[проверка отдельного ключа расчётом/симуляцией](power-review/README.md).
Владелец решил заказать базовый комплект из 7 деталей для макета через EN;
отдельный ключ сохранён как запасной. Оплата/получение не подтверждены. EN-топология
не симулирована, связи платы и аппаратные испытания ещё впереди. Номиналы выбраны
для макета, окончательная монтажная схема и серийный BOM не утверждены.

## Требуемое управление двумя кнопками

Владелец выбрал принцип удержания питания: кнопка A временно питает электронику,
ESP32 подтверждает удержание обеих кнопок четырьмя сигналами и разрешает самостоятельную работу;
выключение через меню после сохранения и отпускания кнопок. Это заменяет прежнее
предпочтение подавать питание лишь после полного жеста. Сон отвергнут.
[Состав макета и границы проверки](button-power-selection.md); физические выводы
кнопок ещё проверяются. Прошивка не адаптирована, аварийный механизм отложен.

После проверки: использовать безопасный при boot/reset GPIO HOLD; GPIO7 пока занят
DS1302, только кандидат после перехода на DS3231. A/B можно читать со встроенными
подтяжками после ранней настройки; реальную проводку проверить на помехи. RESET,
снимающий HOLD, может выключать устройство вместо перезапуска. USB-развязка ещё не
определена: один P-MOSFET не блокирует обратное питание, а отключение EN также
не доказывает обратной блокировки. Наличие контакта EN подтвердил владелец;
соединение с VIN и функция OFF не проверены. В EN-варианте измерительные входы
INA219 перед преобразователем остаются под батарейным напряжением при VCC=0;
утечки и отсутствие подпитки проверить отдельно. Все основные потребители должны
находиться после отключаемого выхода, иначе через EN они не выключатся.
