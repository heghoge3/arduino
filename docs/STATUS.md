## Проработка цикла похода, 10.11.2026

[Спецификация](hike-lifecycle.md) содержит принятые решения: экран от любой кнопки,
15 секунд бездействия; ночёвка в том же походе с автоматическим привалом. Q1 согласован:
после сбоя спросить «Продолжить / Завершить». Q2 согласован: при выключении спросить
«Завершить текущий поход? Да/Нет»; «Да» закрывает поход, «Нет» сохраняет незавершённым
для вопроса о продолжении при следующем включении. START/END/RESUME и Q1 теперь
реализованы; аппаратное выключение по Q2 пока нет.
Раскладка будущего меню, аварийное выключение при ошибке SD и бюджет потери данных
остаются открыты. Сохранение HOLD во сне и при пробуждении V2 проверить на макете.

## Первый этап реализации, 10.11.2026 — история 0.1.20/0.10.3

Владелец разрешил начать работу над приложением и прошивкой. Исходники первого этапа:
**ESP32 0.1.20, Android 0.10.3 (versionCode 26)**. Это не новые подтверждённые установки
и не замена ссылок на выпущенные сборки в таблице выше.

- V1 с OLED: любая кнопка будит экран, первое нажатие/удержание только включает его.
  После отпускания следующие нажатия выполняют прежние действия A/B. Экран гаснет
  через 15 секунд бездействия; при удержании таймер ждёт отпускания. Обновления
  датчиков не продлевают таймер. Пробуждение из внутреннего сна тоже обработано.
  Без обнаруженного OLED сохранены прежние действия кнопок без обязательного
  пробуждения экрана. В этой версии удержание B открывало сопряжение; в 0.1.21
  оно открывает меню похода, сопряжение перенесено в его отдельный пункт.
- Android: главная различает свежие показания и сохранённые. При отсутствии свежих
  данных графики/показания на главной свёрнуты, доступны по явному раскрытию; есть
  дата, пояснение неизвестного состояния и действие подключения/запроса показаний.
  История, карта и графики остаются доступны отдельно; потеря BLE не объявляет END.
- Свежесть подтверждает только STATUS текущего подключения; INFO, выгрузка истории
  и восстановление базы её не подтверждают. После 5 секунд без STATUS данные считаются
  устаревшими (проверка UI раз в секунду). На Android используется время с учётом сна
  телефона, независимое от календарных поправок. После переподключения нужен новый STATUS.
- Метка, хлопушка и переключение записи защищены от отправки без свежего состояния;
  очередь повторно проверяет соединение/свежесть непосредственно перед отправкой.
  Действие со старого подключения не переносится в новое. Уведомление достижения
  также требует свежего состояния. Настройки/синхронизация не заблокированы этим правилом.
- «Вкл/Выкл GPS» заменено на «Пауза/Продолжить» с пояснением, что датчики продолжают
  записываться и это не завершение похода. Тексты GPS больше не называют подозрение
  доказанной подменой, не обещают восстановленный путь по шагам и точность из HDOP.
  Сам алгоритм GPS/географические зоны в этом этапе не изменены.

Проверки первого этапа:

- `pio test -e native`: 50/50, включая пять новых сценариев кнопок/таймера,
  переполнение millis, пробуждение и работу без экрана.
- `pio run -e s3 -e s3_fake`: обе сборки успешны; на устройство не прошивались.
- `testDebugUnitTest`: полный набор 127/127; после добавления проверки всей главной
  отдельно повторён ReadingsNoticeTest — 3/3 (один новый сценарий). Проверены
  восстановление кэша, отсутствие STATUS после переподключения, истечение свежести,
  запрет отложенной команды после смены соединения и недоступные кнопки в истории.
- [Главная без связи](software-evidence/2026-11-10/home-saved.png): снимок теста
  Robolectric с искусственными данными, не телефона владельца. Проверено раскрытие
  сохранённых показаний и блокирование команд. Это не полевая проверка BLE/SD.

Среда: `/workspace/tooling/activate.sh`; для Android использованы
`-Pkotlin.compiler.execution.strategy=in-process` и внешний Gradle init с
`tasks.withType(Test).configureEach { systemProperty 'user.home', '/workspace/tooling/test-user' }`.
Это обходит недоступный для записи служебный каталог тестов без изменений проекта.

Подписанный APK 0.10.3 не выпускался; существующий постоянный ключ не менялся,
новый не создавался. Восстановление резервной копии остаётся непроверенным по
[инструкции подписи](android-signing.md). Испытаний на телефоне/плате нет.
Следующий выполненный этап S4/S5 описан ниже. LCD/RTC/HOLD V2 по-прежнему требуют
отдельной адаптации и аппаратной проверки; текущая прошивка остаётся для V1.

## Завершение с телефона и гаджета, 10.11.2026

Текущие исходники: **ESP32 0.1.21 / Android 0.10.4, versionCode 27**.
Владелец отдельно поручил реализовать завершение обоими способами.
[Инструкция и контракт](hike-lifecycle.md), [формат обмена](protocol.md).

- START, FINISH, RESUME разделены. Включение само не начинает запись; END не
  создаёт новый поход. После сбоя — согласованный выбор «Продолжить / Завершить».
  Внутренний сон/CAMP остаётся тем же походом без повторного вопроса.
- END сбрасывает накопленные точки, затем сохраняет состояние в NVS с чтением
  обратно. Ошибка не выдаётся за успех. ID/ревизия/квитанция защищают от повторов
  и устаревшего запроса. Отдельная копия .end позволяет подтвердить окончание
  известного телефону прежнего похода; полного импорта SD нет.
- V1 OLED: удержание B открывает меню, A выбирает, короткое B открывает подтверждение,
  новое удержание B 1,5 с подтверждает; A отменяет. Первый жест после гашения только
  будит экран. Без OLED цикл доступен из приложения.
- Android: отдельные диалоги, сохранённое намерение до отправки, честное неизвестное
  состояние при потере ответа, восстановление без автоматического повтора команды.
  END хранится в истории независимо от полноты копии; Room 4 → 5 без удаления данных.
- Старое NEW_HIKE отключено в новой прошивке. Для установки нужен согласованный
  комплект приложения/прошивки; установленный APK 0.10.1 этого цикла не поддерживает.

Проверки: **57/57 native**, **135/135 Android JVM/Robolectric**, обе сборки
**s3/s3_fake успешны**. Проверены переходы, повторы, сохранение/восстановление,
ошибка записи/чтения подтверждения, потеря ответа, устаревший диалог, миграция,
подтверждение/отмена интерфейса и офлайн-блокировка. [Снимок карточки завершения](software-evidence/2026-11-10/hike-ended.png)
получен в Robolectric на искусственных данных (включая тестовую дату); это не фото телефона.

Сборки на прибор не прошивались. Подписанный APK 0.10.4 не выпускался; доступ к
существующему приватному ключу/резервной копии не подтверждён, новый ключ не создавался.
Ссылки на последние выпущенные артефакты в начале документа не заменены.
На V1 нужны испытания реальных BLE/SD/NVS, отключения питания и кнопок по чек-листу
в спецификации. Допустимая потеря буфера при внезапной разрядке Q5 остаётся открытой.
Полное выключение Q2, GPIO HOLD и экран/RTC V2 этим этапом не реализованы.

## Перенос V2, исходники 0.1.22 — история до назначения HOLD

[Реализация и условия запуска](firmware-v2.md): DS3231 вместо DS1302, MPU 0x69,
кандидат профиля ST7567 вместо SSD1306, пассивный зуммер. Подготовлены A+B/четыре
сигнала и выключение с вопросом «Завершить поход? Да/Нет» при настроенном HOLD.
Владелец подтвердил, что GPIO HOLD, адрес LCD и подключение подсветки пока не
определены. Поэтому HOLD=-1: автономное управление питанием недоступно по умолчанию.
Нет утверждения, что гашение изображения отключает подсветку. Установка не выполнялась.

Проверки этого этапа: 60/60 native-тестов, сборки s3 и s3_fake успешны.
Добавлены проверки календаря/BCD/12-часового режима RTC и непрерывного жеста A+B,
включая прерывание и переполнение millis. Ошибки/просадки реального I2C/NVS/SD,
инициализация конкретного LCD, звук и сохранение HOLD во сне аппаратно не проверены.
Android не менялся и повторно не тестировался в этом этапе; подписанный APK не выпускался.

## Назначение HOLD, исходники 0.1.23

По прямому поручению владельца выбран GPIO7: освободился после удаления DS1302,
не пересекается с текущими программными назначениями, поддерживает RTC hold ESP32-S3.
GPIO7 → анод D2 (1N4148); катод D2 → EN по выбранной схеме. По умолчанию управление
питанием включено и требуется жест A+B. Стенд без EN: `V2_POWER_HOLD_PIN=-1`.
Это заменяет прежнее неназначенное состояние 0.1.22. Монтаж, boot/reset, удержание
во сне и физическое отключение ещё проверить; аппаратная готовность не объявлена.
Обе сборки s3/s3_fake с HOLD=GPIO7 прошли; прошивка на устройство не устанавливалась.

## Доступность контактов V2

По фото и перечню владельца исключены GPIO45/42/41/40/39/38/18/17/16/15/14.
Ни один из них текущей прошивкой не используется; переноса назначений не потребовалось.
Альтернативные HOLD GPIO14–18 убраны; в pins.h добавлена проверка исключённых выводов
при сборке. HOLD — GPIO7, остальные подключения сохранены. Версия исходников 0.1.23.

## Эмулятор V2, исходники Android 0.10.5 (28)

По отдельной задаче владельца существующий эмулятор обновлён на месте. Второй старый
режим не поддерживается; генератор датчиков/маршрута и прежние записи телефона сохранены.
[Инструкция и ограничения](emulator-v2.md).

- Первый запуск IDLE; явные START/END/RESUME через тот же байтовый кодек и репозиторий,
  что у BLE. END не начинает новый поход. Перезапуск прибора требует решения по прежнему ID.
- Панель сценариев: ошибка/восстановление SD, потерянный ответ, разрыв связи,
  внезапное отключение/разрядка, штатное выключение с завершением и без него.
- Независимое от телефонной копии сохранение виртуального прибора с CRC32,
  проверкой отказа записи и восстановлением после перезапуска приложения.
  Отдельно проверено сохранение байтов записанного трека/меток.
- 143/143 Android JVM/Robolectric-теста успешны: новый набор проверок V2, панель
  сценариев и регрессии. [Снимок панели](software-evidence/2026-11-10/emulator-v2.png)
  — искусственные данные Robolectric, не телефон владельца.

Прошивка этим этапом не менялась. Эмулятор исполняется в процессе приложения,
не запускает C++ ESP32 и не доказывает поведение электроники/расход/качество GPS.
Есть документированные ограничения checkpoint и аппаратных настроек.
На момент завершения этапа эмулятора APK ещё не выпускался. Последующий выпуск
0.10.5 и восстановление ключа описаны ниже; установка на телефон не подтверждена.

## Повторный анализ GPS, 11.11.2026 — история до политики 2

Владелец попросил оценить оптимальность текущей фильтрации и предложить исправления.
[Результат](gps-filter-review.md): две зоны по-прежнему безусловно блокируют реальные
визиты; Android дополнительно фильтрует маршрут/метки/историю. Синтетическая проверка
действующего ядра показала отказ после разрыва 30 с при движении 72 км/ч и последующее
зависание восстановления, а также отказ по паре SNR+барометр без пространственного
противоречия. PHONE+TIME (540 с) сами по себе координаты не отвергают.

Предложены контекстная роль зон, свежесть NMEA и монотонные интервалы с учётом сна,
отдельные сомнительные сегменты, сохранение исходников и согласованное изменение обеих
частей. Предложения не реализованы и не означают автоматического запуска S1–S3.
Проверки — небольшая программа с текущим spoof.cpp, не запись реального похода.
Код/настройки/версии/сборки не менялись, новые APK/прошивка не выпускались.
Установленная ESP32 по-прежнему неизвестна; владелец сообщил, что 0.10.5 ещё не установил.

## Первый этап GPS, исходники прошивки 0.1.24 — история

По поручению владельца начаты G1/G2: [диагностика и свежесть NMEA](gps-diagnostics.md).
GGA должен быть свежим и соответствовать времени текущего RMC; невалидный HDOP и
старые данные не принимаются в геометрию. SNR используется только со свежим GSA той
же системы и полной последовательной группой GSV. Это не новая географическая политика:
два круга пока блокируют координаты, пороги скачка/восстановления ещё прежние.

Добавлен выключенный по умолчанию gpsdiag on/off: ограниченная запись входа, состояния
детектора и решения на SD; хостовый проигрыватель проверяет решение без вывода координат.
Возраст сообщений измеряется по времени приёма; UTC-интервалы самого детектора и PHONE_POS
в протоколе ещё не переработаны. Полный NMEA/UART и контрфактический прогон новой политики
этим этапом не реализованы. Реальный trace не публиковался.

Проверки: 65/65 native, обе сборки s3/s3_fake успешны. Синтетический trace из трёх записей
повторён с 0 несовпадений; повреждение/усечение отвергаются. Проверены неполные/старые
сообщения, отдельные созвездия, полночь, переполнение таймера, сохранение состояния
восстановления и все прежние проверки фильтра. На реальном устройстве не испытывалось.
Android/пакеты BLE не менялись; новый APK и устанавливаемая прошивка не выпускались.
Эффективность против реальной подмены и бюджет записи/энергии не измерены.

## GPS: программная обработка политики 2, 0.1.25 / 0.10.6

Владелец разрешил перейти к оставшимся этапам. Реализованы G2–G4:
[единая спецификация фактического поведения](gps-policy-v2.md).
Географические области теперь только контекст; Android не исключает по ним
координаты маршрута, меток, телефона и истории. Расхождение часов/телефона и
пары слабых признаков не объявляют координаты ложными. Необъяснимый скачок
сохраняется как непроверенный участок, отдельно от принятой геометрии.
Одной стабильности и истечения таймера недостаточно для восстановления.

Возраст телефона включает исходное измерение и ожидание отправки; источник
передаётся отдельно. Интервалы детектора монотонные с учётом внутреннего сна,
UTC используется отдельно. Новые признаки политики/непроверенных точек/разрывов
сохраняются в POINT без изменения длины; их учитывают SD, база, карта и дистанция.
Старые записи не объявляются проверенными задним числом. GPS2 trace сохраняет
новое состояние; GPS1 воспроизводится прежней политикой только для диагностики.
Эмулятор передаёт новые признаки, но не запускает C++ фильтр.

Проверки итогового кода: **77/77 native, 151/151 Android JVM/Robolectric**,
обе сборки s3/s3_fake успешны. Проверены реальные координаты внутри области
на синтетическом входе, 30-секундный разрыв при 72 км/ч, длительный скачок,
опоры/возраст/очередь телефона, часы, флаги записей, границы коррекции и сохранность
шаговой дистанции, повторные сообщения в одну секунду. GPS1 и GPS2 искусственные trace — по 3 записи, 0 несовпадений.
Это программные проверки, не результаты реального посещения или воздействия.

Нужна согласованная пара прошивки 0.1.25 и APK 0.10.6: новое приложение не меняет
прошивку ESP32, старая версия приложения может продолжать географическую фильтрацию.
На прибор/телефон новые версии исполнителем не устанавливались. Установленная
версия ESP32 неизвестна. Полевая G5 и калибровка впереди: нужны реальные посещения
областей, переезды/тоннели и новые эпизоды подозрительных данных с trace.
Когерентную подмену с холодного старта без независимой опоры программно гарантированно
не отличить. Нулевые ошибки и готовность к продаже не заявляются.

## Минимальный профиль ползунка, исходники 0.1.26

По отдельному согласованию владельца выполнен [PWR0 / OTA0](slider-power-v2.md):
экспериментальный s3_slider_bench без физического GPIO, ранний HOLD без A+B,
устойчивый OFF → сохранение точки/буфера/того же ID в RECOVERY → проверка NVS/SD/журнала
→ снятие HOLD. Ошибка сохранения оставляет HOLD и остановленную запись. Возврат ON
не продолжает поход автоматически. На этапе 0.1.26 A+B/menu ещё был default; последующее решение 0.1.27 ниже.

89/89 native, из них 12 новых; s3/s3_fake/s3_slider_bench собираются. Дополнительно
проверены compile-time отказы для неназначенного/занятого/запрещённого GPIO и реального
GPIO в bench. Проверки readback в native используют подставное хранилище; настоящая
запись на SD/NVS, OFF во время записи, питание EN при reset и rollback на V2 не испытывались.
Новый аппаратный GPIO не выбран: нужны проверка RTC-пробуждения и распределения выводов.

В core есть контракт OFF для стадий будущего OTA: abort неактивной записи, ожидание
flash-critical, сохранение выбранного слота и отсутствие принудительного mark-valid.
Реального приёмника/abort/смены слота/отложенной самопроверки ещё нет; main работает
с фазой None. Это не доказательство сохранности прошивки после оборванной передачи.
Android не менялся, новые APK/прошивочные архивы не выпускались, рабочая huge_app прежняя.
Последующая передача/подпись и аппаратная приёмка остаются отдельными этапами.

## Основной ползунок, исходники 0.1.27

По новому прямому решению владельца основной профиль изменён на Slider=1.
A+B не является default или скрытой заменой: остаётся только явным legacy=0.
До назначения проверенного GPIO основная автономная сборка **останавливается**,
а не использует виртуальное положение ON. s3_slider_bench и native включают bench
явно. CI строит и публикует только артефакт с именем USB bench, не автономную прошивку.

Проверки: 89 native, 11 compile-probes, сборка s3_slider_bench; s3/s3_fake ожидаемо
отклоняются сообщением о неназначенном GPIO. Четыре host-регрессии энергосбережения
также проходят. Из CI исключён неработающий исторический host-тест DS1302 (его исходник
сохранён); DS3231 проверяется native-набором, нового I2C integration-теста не добавлялось.
Аппаратный вход не выдумывался;
проводка, EN, OFF из сна, SD и reset/rollback на V2 остаются непроверенными.

## Что пока не готово

- [Основное питание](slider-power-v2.md): владелец выбрал ползунок ON/OFF основным.
  Независимый ON→EN, чтение положения GPIO и сохранение перед снятием HOLD ещё
  требуют макета. Предыдущий [вариант A+B](hardware-v2/button-power-selection.md) — история.
  Площадка EN видна на присланном скриншоте купленного преобразователя;
  владелец решил заказать базовые 7 деталей для макета через EN. Оплата/получение
  новых деталей не подтверждены; связь EN с VIN ещё неизвестна.
  На фото одна сторона платы продавца; экземпляр и функция OFF не проверены.
  Расчёт и ngspice [отдельного ключа](hardware-v2/power-review/README.md) сохранены
  как проверка запасного варианта; на EN-топологию они не распространяются.
  Аппаратной проверки нет; микросхема модуля, ток OFF, GPIO HOLD и USB-развязка неизвестны.
  Сон как выключение отвергнут; аварийный механизм отложен, RESET не равен обесточиванию.
- [Индикация зарядки](hardware-v2/charging-indication.md): владелец выбрал два внешних
  LED после отказа от сложной схемы и окошка; кнопки без подсветки. Предложено заменить
  штатные LED TP4056 внешними с сохранением резисторов. Заказ светодиодов подтверждён
  владельцем; получение и монтаж не подтверждены;
  площадки, ток, состояния и работа при зарядке ещё проверяются. Код не менялся.
- BLE OTA: [анализ V2](ble-ota-v2.md) и [этапы OTA1–OTA7](software-roadmap.md#ble-ota-v2)
  сохранены; выполнен только минимальный [PWR0 0.1.26](slider-power-v2.md). Приёмника нет.
  Базовая clean-сборка 0.1.25 —
  bin 728784 байта (не прежние 708816). Предложены два слота по 1,5 МиБ с сохранением
  разделов данных; рабочая разметка пока huge_app. Arduino default преждевременно
  подтверждает boot; старый cold/reset путь HOLD сохраняется только в явном legacy-профиле,
  новый Slider работает без жеста только как USB-стенд с виртуальным входом. Физическая flash,
  USB-переход, первый boot/rollback и питание на реальной V2 не проверены.
  APK 0.10.6 не содержит OTA-функции; новые APK/устанавливаемая прошивка этой задачей не выпускались.
- Прошивка V1 не объявляется готовой для новых DS3231 и LCD без адаптации.
- Точные размеры корпуса, разводка, автономность и прочность V2 ещё не проверены.
