# Постоянный ключ прошивки V2

12.11.2026, реализация BLE OTA. Это отдельный ключ **прошивки**, не ключ APK.
[Контракт OTA](ble-ota-v2.md), [постоянная подпись Android](android-signing.md).

## Что создано и где хранится

Один ECDSA P-256 ключ создан в разрешённой задаче. Публичный ID:
`a128f28662e56efc` (первые 8 байт SHA-256 DER SubjectPublicKeyInfo).
Публичные данные закреплены в `firmware/ota/public-key.h` и
`android/app/src/main/assets/firmware/public.der`. Их можно публиковать.

Приватный PKCS8 и резервный ZIP в текущей среде лежат **вне репозитория**, в
`/workspace/private-signing/ota-v2-signing-key.pem` и
`/workspace/private-signing/ota-v2-signing-backup.zip`, права 0600. Это локальное
хранение, не гарантия доступности в следующем чате/среде. Приватный архив не зашифрован:
его копии хранить в защищённом хранилище, отдельно от публичных сборок.
Резервная копия локально создана; загрузка в ChatGPT Library, внешнее хранилище
или получение владельцем **не подтверждены**. Постоянное внешнее хранение ещё нужно обеспечить.

Не печатать приватный ключ, конфигурации/пароли и содержимое ZIP в ответах/логах.
Не включать их в GitHub, APK, USB-комплект, CI-артефакты или публичную ссылку.
Ключ APK не изменён. При утрате OTA-ключа **не создавать замену молча**: существующие
приборы её не примут. Механизм ротации/отзыва пока не реализован; потребуется отдельный
план, возможно USB-переход. Обновление public key в одном APK не меняет доверие ESP32.

## Выпуск следующего образа

1. Считать текущую основную ветку, сохранить номера модели/проводки/профиля/разметки;
   несовместимое изменение требует нового контракта. Проверить старый rollback-слот
   и обратную совместимость данных. Увеличить продуктовую версию/release.
2. Собрать `pio run -d firmware -e s3`; проверить настоящий app-only бинарник, бюджет
   и продуктовую metadata. Не подменять его fake/bench/merged flash.
3. Проверить доступ к **сохранённому** OTA-ключу; инструмент сверит его публичную часть
   с обоими pinned public key. Подписать вне публичного CI:

```sh
python3 firmware/tools/package_ota.py --key /PRIVATE/ota-v2-signing-key.pem \
  --image firmware/.pio/build/s3/firmware.bin --out android/app/src/main/assets/firmware
python3 firmware/tools/verify_ota_bundle.py
```

Нужен Python с `cryptography`; скрипт **не генерирует ключей**. Private key не записывается
в вывод. В git коммитятся только app.bin, manifest.bin и public.der. Manifest — 72 байта
канонических полей + ECDSA raw r/s по 32 байта; он подписывает SHA-256 полного app.bin.
Публичная CI-проверка не требует секретов и не пересоздаёт подпись.
4. Собирать APK прежним постоянным APK-ключом; проверить сертификат и точное совпадение
   assets с принятым образом. Не каждый APK должен содержать новый образ/требовать OTA.
5. Успешные статические проверки/сборка не заменяют приёмку на V2, особенно rollback
   и сохранность NVS/SD. Приватную полную копию flash не публиковать: там могут быть bonds.

## Граница защиты

Подписанный manifest проверяет происхождение и совместимость в работающей прошивке.
Secure Boot, flash encryption и eFuse anti-rollback не включались. Программный release
в NVS не защищён от физического перепрограммирования; USB-комплект предназначен владельцу
и не является криптографически защищённым установщиком. Эти ограничения нельзя выдавать
за защиту серийного изделия от физического вмешательства.
