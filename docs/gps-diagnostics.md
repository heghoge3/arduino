# GPS: диагностика и первая защита свежести

11.11.2026, исходники прошивки V2 0.1.24. Выполнена программная часть G1 и начало G2
из [аудита фильтра](gps-filter-review.md). Это ещё не новая географическая политика:
зоны блокируют координаты по-прежнему, скачки и восстановление пока используют прежние
правила. APK 0.10.5 и BLE-пакеты не менялись; нового выпуска для установки нет.

## Что изменилось в обычной работе

- Для допуска к текущей проверке нужны RMC не старше 3 с и GGA не старше 2,5 с,
  с положительным качеством и согласованным временем суток (разница не более секунды,
  включая переход через полночь). Это допускает обычный порядок RMC перед GGA.
- HDOP NaN/нулевой, старый GGA, неполный GGA или несовпадение эпох не превращаются
  в подмену: точка не принимается в GPS-геометрию, остаются шаги и датчики.
- SNR для каждого созвездия требует собственного свежего GSA (≤3 с) и полной,
  последовательной группы GSV (последняя полная группа ≤10 с). Группа должна собраться
  за ≤3 с; пропуск/перестановка/повтор части делает её непригодной для проверки SNR.
  Свежий BeiDou не «омолаживает» устаревшие GPS-спутники.
- Возраст считается по millis() получения, не UTC телефона/спутника. Парсер сбрасывает
  метаданные при сбросе GPS; переход через переполнение millis проверен.

Пороги — начальные технические ограничения, не измеренный оптимум для экземпляра
ATGM336H. При редкой настройке GSV SNR может оказаться недоступным: это означает
отсутствие этого признака, а не автоматическое признание координат достоверными.
Первые пять проверок стабилизации, географический запрет и пространственные правила
не отменены. Полная проверка даты RMC, монотонные интервалы самого детектора через сон,
возраст PHONE_POS в протоколе и новая модель восстановления остаются дальнейшими G2–G4.

## Запись диагностического файла

Режим **выключен по умолчанию**, не включает GPS/радио и не меняет настройки маршрута.
На собранном V2 через USB-консоль:

- `gpsdiag on` — включить запись текущих проверок;
- `gpsdiag off` — остановить, сохранив файл.

Файл `/logs/gnss-trace.bin` на SD содержит координаты прибора и телефонной опоры.
Не публиковать его автоматически. Предел — 512 записей на включение режима и 1 МиБ
общего файла; достижение предела/ошибка записи отключают диагностику с сообщением.
Повторное включение добавляет записи, не удаляет предыдущие. При полном файле
сначала сохранить копию, затем освобождать файл вручную. Неполную запись после
отключения питания проигрыватель сообщает как ошибку, не скрывает повреждение.

Режим и счётчик переживают обычный внутренний сон; холодный запуск их сбрасывает.
Запись дополнительных данных повышает обращения к SD/потребление, поэтому режим
не включён постоянно. На реальном комплекте скорость записи/влияние на UART ещё
проверить. Для получения файла нужен доступ к SD: выгрузка бинарного trace в Android
не реализована, SYNC_LOG передаёт обычный журнал. Это не импорт SD.
Прошивку V2 не устанавливать на старый комплект V1 ради этой диагностики.

Каждая запись содержит:

- полное состояние детектора **до** решения: пороги, зоны, телефонную опору,
  последнюю принятую точку, состояние неподвижности и восстановления;
- фактический Input: исходные координаты, обе шкалы UTC/доверие, высоты и их
  пригодность, использованные SNR, шаги;
- номер загрузки/ID похода, время приёма, возраста последних сообщений
  RMC/GGA/GSA/GSV, HDOP/спутники/качество, допуск свежести, маску свежих систем SNR;
- факт вызова детектора и результат (отказ/маска). Для стабилизации/плохого качества
  сохраняется запись без вызова детектора, не придумывается решение о подмене.

Возраста четырёх сообщений — общие последние сообщения соответствующего типа;
это **не** полный список эпох/возрастов всех спутников. Решение об использовании SNR
проверяет каждую систему отдельно. Полный сырой поток NMEA, сообщения с неверной
контрольной суммой и причины отбрасывания на уровне UART здесь не записываются.

Формат GPS1: заголовок с длиной, явные поля little endian без указателей/паддинга,
контрольная сумма FNV-1a. Размер ограничен 1200 байт, число зон/спутников проверяется
при чтении. Это проверка целостности, не криптографическое подтверждение координат.

## Повторное проигрывание на компьютере

Из корня репозитория:

```sh
g++ -std=c++17 -Wall -Wextra -I firmware/lib/core \
  firmware/tools/replay_gps_trace.cpp firmware/lib/core/spoof.cpp -o /tmp/gps-replay
/tmp/gps-replay /path/to/gnss-trace.bin
```

Для проверки без устройства есть генератор **искусственного** trace:

```sh
g++ -std=c++17 -I firmware/lib/core firmware/tools/create_synthetic_gps_trace.cpp \
  firmware/lib/core/spoof.cpp -o /tmp/gps-fixture
/tmp/gps-fixture /tmp/synthetic-gnss-trace.bin
/tmp/gps-replay /tmp/synthetic-gnss-trace.bin
```

Код 0 — все проверенные решения совпали; 1 — есть несовпадение; 2 — ошибка файла,
формата или повреждение. Вывод содержит только счётчики, без координат/телефонных опор.
Записи плохого качества считаются отдельно, а не пропускаются незаметно.

Это воспроизведение **отдельных решений действующего ядра из сохранённого состояния**.
Оно позволяет отличить «так решил детектор» от ошибки показа/транспортировки. Это ещё
не непрерывный контрфактический прогон новой политики: нельзя подставить её в старые
опоры и объявить измеренной эффективность. Такой прогон с событиями времени/настроек
и размеченными нормальными/подозрительными данными остаётся следующим этапом.
Для точного воспроизведения сохранить версию прошивки и соответствующие исходники.

## Проверки

Native: сериализация состояния зон/PHONE/TIME и восстановления; порча/все усечения
записи; возраст при переполнении таймера и сбросе; старый/несогласованный/неполный GGA,
полночь, свежесть по созвездиям и неполный GSV. Все прежние проверки фильтра сохранены.
Хостовая программа проверена на трёх искусственных записях: несовпадений 0; порча и
обрыв файла корректно отклоняются. Это не воспроизведение похода владельца.
Итоговые результаты сборок — [STATUS.md](STATUS.md).

После этого этапа задача не закрыта: требуется G2 по оставшимся шкалам времени и
телефонному измерению, G3 по географическим областям одновременно с Android,
G4 по сегментам/восстановлению и реальные данные для G5.
